# F001：主动停用 controller 后，直接 shutdown 与 Nav2 bond 自动恢复竞态

日期：2026-10-29 Asia/Shanghai。AI 工程因果分析；本人理解、独立抽查和目视均待确认。

失败回合：/home/robot/commercial_mobile_robot/evidence/runs/p0-08-fault-v6vn6igl-r02-f02-a002。目的：DWB F-C 主动故障注入，不能包装成自然发生的控制器故障。

## 原始事实

同一目标已接受、实际运动达到冻结门槛，然后单次 deactivate，GetState 确认生效；Action 实际 ABORTED。异常停车窗口成立，但最终 cleanup=FAILED，不计故障处理通过。

原始入口：
- runtime/fault-events.jsonl：资格、请求、实际激活、观察与停止事件，各含 UUID、monotonic 和源仿真时间。
- logs/action-client.jsonl：接受与真实 ABORTED；取消回应不替代终态。
- runtime/failure-stop.json、runtime/observations.jsonl、bag/：停车及命令原始记录。
- logs/navigation.log 第 407–436 行：manager 正在逐个激活恢复节点时，worker 同时逐个 shutdown。
- runtime/cleanup.json：navigation 子树强制升级 TERM/KILL、exit=-15、remaining=[]；退出了但不是正常清理成功。
- /home/robot/commercial_mobile_robot/evidence/env/p0-08-dev-v6vn6igl/F001-raw-timeline.json：原始故障事件摘录，不能将 wall 与 sim 两轴相减。

## 支持的原因与边界

worker 的直接合法 lifecycle transition 在单个节点上成功，并不足以协调 manager 的并发恢复。原始日志证明两条状态改变路径重叠；这是本次清理实现的竞态。Nav2 1.3.13 源码的 bond 检查会 reset 并在节点可访问后自动 startup，与日志吻合：https://raw.githubusercontent.com/ros-navigation/navigation2/1.3.13/nav2_lifecycle_manager/src/lifecycle_manager.cpp 。

不能据此宣称 DWB 算法失效、保护失效或实车安全问题。旧 MPPI 同类回合曾正常退出，也不能排除竞态。

## 最小修复

保留 bond、自动恢复和所有控制参数。停车观测结束后，在原 runner 的 cleanup 预算内有界等待 manager is_active 且全部实际节点 active，再调用 manager SHUTDOWN，核对全部 finalized。等待子预算 25 秒，仍嵌套于原 cleanup 60 秒；无法稳定时保留失败与自有进程后备收尾。调度器仍不操作 ROS 生命周期。

旧版本在 evidence/env/p0-08-dev-v6vn6igl/revision02/；修复依据 fix02-basis.json；隔离反例 protocol-02.xml（5 passed）覆盖未就绪不发 shutdown 和稳定后单次关闭。新正式批次重新编号 r05，旧失败和旧 cohort 全部保留。
