## 3. 已实现与核心调用关系

`MissionCommand` → deferred service callback → `Runtime::call`有界邮箱 → 原`Store::submit/apply`事务 → 原FSM → 已提交effect → `NavigationAdapter::execute`有界命令队列 → 主线程executor中的`tick/async_send_goal` → Fake。

真实Action回调 → 每次Goal专属身份context → 共用`ActionCorrelation`有界归并 → owner事件邮箱 → SQLite；响应必须等事务结果ready后发送。接受晚到先绑定handle/UUID再精确取消，不用cancel_all。Cancel ACK、Action终态、synthetic停止和业务完成分别记录。

新增`cmr_interfaces`三种最小服务、普通Mission Node、薄Action适配、共用纯关联边界、真实NavigateToPose Fake、协议监督器、独立审计、A01–A20矩阵。保留OFF不依赖ROS和ON安装模式。主进程单线程executor，Runtime唯一owner线程；Fake三线程/独立控制callback group和mutex目标表，无detach。

deadline到期比较为>=；接受/结果callback本身也核对steady期限，避免wall timer调度间隙。旧operation Fatal转无状态审计，不影响新返程。只有通过关联的终态停止该Goal监控。关键事件有界重试与故障锁存，反馈允许丢弃并计数；没有无限队列。Node与Adapter使用weak引用避免强引用环。

详见[合同](../contracts/p1-action-v1.md)、[六模块源码导读](../design/p1-action-design.md)、[可复制命令](../guides/mission-action-tests.md)。每个模块包括实际配送问题、架构位置、类/函数/线程数据流、开源取舍、验证范围与五个问题及答案。

## 7. 必须掌握的原理与交付边界

1. **事务不包住ROS发送。** 先持久化意图再调用外部动作仍存在崩溃窗口；不确定时暂停占槽、不自动重发。Exactly Once不是本实现的承诺。
2. **Action不决定业务状态。** SUCCEEDED只是导航层事实，交接、返程和完成由原FSM结合独立到达/停止决定；取消先提交后成功只留原始结果。
3. **身份分层。** Mission是订单，Operation是去/返程，Attempt是一次尝试，UUID是ROS Goal，process_epoch区分进程。不能用全局current_goal推断所有回调。
4. **异步不等于无限后台线程。** executor回调只做有界工作，owner提交后延后响应；不在回调里等待同executor才能完成的future。weak_ptr和join/停止顺序共同保证生命周期。
5. **Cancel ACK不是停车。** handle晚到仍须关联并精确取消；Cancel ACK、终态、撤销授权与停止证据分别处理。shutdown/Client析构也不保证Server目标停止。

**已实现：** 代码、双构建、接口合同、薄适配、Fake、监督器/审计器、矩阵和教学文档。**静态检查通过：** diff/范围/所有权和OFF依赖检查。**离线执行通过：** 原16组与当前17组及核心ASan/UBSan。**真实ROS验证通过：** 表内真实Action/业务服务/图与启动各自层级；A11仅声明共用适配单元+fixture层。**尚未验证：** TSan、真实授权/Gate、物理停车、Gazebo/Nav2真实导航、底盘、跨机故障与生产配送、个人独立掌握。

有限关闭窗口1600ms属于协议收尾预算，SQLite或OS不可中断I/O不提供硬实时退出保证。SIGKILL无法执行关闭；恢复保持PAUSED/UNCERTAIN；Fake被回收不构成物理安全证据。已有历史错误DB不自动迁移。

P1-03交接点是原ExecutionPort、identity/epoch与停止新鲜度合同；后续替换synthetic授权/停止源，继续保留NavigationAdapter与Mission/Store语义。当前不自动开始Gate或任何下一阶段。个人理解及正式放行由用户完成，本文不代签。
