## 实际数据流与模型

既有 `validate_run.py run`（不带 allow-fixtures）→冻结源文件指纹→归档 Scene 根模型/链接 ID→`runtime/gazebo-raw.jsonl` 的实际 Pose_V 源 stamp→实际链接姿态检查碰撞体包含关系→标准化中心→原始间隔检查→两对象时间断点并集、有界插值→每个有效线性段最小距离→新的分析目录。控制目标/运动脚本只用于确定预声明时间范围，不提供实际位置。AMCL、odom、服务应答、指令轨迹不当真值。

四轮实体身份由各自 Scene 核实为机器人 `turtlebot3_waffle` ID 47、道具 `scripted_obstacle` ID 41；代码不硬编码 ID。源接口 `/world/default/pose/info`，Gazebo world frame；每轮独立 clock_epoch。中心偏移明确取模型原点 [0,0,0]，仍保留原始四元数和变换表达；没有把 map 或 AMCL 坐标冒充 world 真值。归档 clock_alignment 显示源时间匹配无平移；原始 GZ 时钟与 Pose_V 分别检查回跳和 epoch。

机器人七个 collision（底盘、激光、两轮、两脚轮、相机）均参与。固定半径：

`R_robot = max(norm(link_translation) + norm(collision_translation) + shape_3D_bound) = 0.2725947818607763 m`。

box 的 shape bound 为半边长向量模，cylinder 为 `hypot(radius, length/2)`，sphere 为半径。这个可解释但偏保守的三维球投影不是最小水平外接圆。随后逐个实际 Pose_V，用真实链接相对姿态检查角点/保守形状界仍在该半径内；观测到最大界约 0.2544105933 m。这个证明只覆盖采样点，不能自动约束未知采样间关节运动。

道具来自归档 cylinder collision，R=0.1 m、height=0.6 m，中心 z=0.3 m，检查直立及零局部偏移；世界高度 [0,0.6]。机器人投影球的保守高度范围约 [-0.2625874,0.2826023] m，不是实体真实最低/最高点；负下界不表示车身穿地。观察到最大机器人倾斜约 0.0056942 rad，三维包络投影不靠“绝对水平”假设漏掉该姿态。

`d = ||p_obstacle-p_robot|| - R_robot - R_obstacle`。对一段相对位移 `q(alpha)=q0+alpha*u`，`alpha*=clip(-dot(q0,u)/dot(u,u),0,1)`；实现先缩放 u，避免微小相对位移下平方下溢。u=0 取段起点；最近时刻不是首次接触时刻。数学切线 d=0，真实边界保持不确定。

冻结区间：唯一目标 accepted 源时间起，终点为 `max(Action terminal+5秒, release+最后运动 knot+hold)`。每对象的原始样本间隔限制为 50 ms，先检查原始括号再插值，不被另一对象的密集样本掩盖；不外推、不跨缺口。全局乱序/回跳拒绝；范围外及 50 ms 边界支持之外的数据计数排除，不参与距离。相同时间的完全相同 pose 可去重，冲突重复拒绝。

当前四轮范围内最大原始间隔均 21 ms。源 stamp 是采样时间，接收墙钟不用于替代它。pose 服务可能跳变/保持，碰撞响应也未由线段重建，因此只评价分段线性模型。数值误差带为 `max(1e-12 m, 64 ULP(scale))`；位置、半径、时间、插值的物理误差分别未知/null，没有拿此数值 epsilon 冒充物理精度。
